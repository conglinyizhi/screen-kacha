screen-kacha

本机屏幕的 HTTP 快照服务。取一张 JPEG 就能看见现在屏幕上是什么，给本地 agent 用。

关于刚刚一闪而过的文本

刚刚你可能看到了一段一闪而过的文本，那段文本是给 agent 看的，用这种方式能让 agent 以更少的成本理解这个服务端的具体作用。

现在你仍然可以在这个页面的最底端看到这段文本，你可以点击这里跳转过去；这样 agent 会读到文本，然后读 llms.txt 文件。而人类几乎不会因此受到太多影响

怎么用

地址都相对于本服务根，下面这些直接能用：

# 拿一张图，存成文件
curl -s -o screen.jpg 'http://127.0.0.1:{{PORT}}/snapshot.jpg'

# 省 token：缩到 1280 宽的 WebP
curl -s -o screen.webp 'http://127.0.0.1:{{PORT}}/snapshot-1280.webp'

# 只要最新的，最多容忍 50 毫秒的旧帧
curl -s -o screen.jpg 'http://127.0.0.1:{{PORT}}/snapshot.jpg?age=0.05'

# 想把鼠标位置也画进去，先去托盘菜单勾上「在截图里标出鼠标位置」
curl -s -o screen.jpg 'http://127.0.0.1:{{PORT}}/snapshot.jpg?cursor=1'

# 只要左上角那一块，比例或百分比都行
curl -s -o corner.jpg 'http://127.0.0.1:{{PORT}}/snapshot.jpg?crop=0.1,0.1,0.3,0.2'
curl -s -o corner.jpg 'http://127.0.0.1:{{PORT}}/snapshot.jpg?crop=10%,10%,30%,20%'

# 服务还好吗
curl -s 'http://127.0.0.1:{{PORT}}/health'

服务在后台持续抓帧，请求直接返回缓存，通常一到两毫秒。 ?age= 是能接受的最大帧龄（秒），想要更新鲜就写小一点， 代价是当场触发一次抓取。

?crop= 的四段是 x,y,w,h，按整帧的比例算（0 到 1）， 带 % 就按百分比，四段可以逐段混用。分隔符只认逗号、分号和空白。 写错、越界、段数不对都会回 400，不会悄悄给整屏。 分辨率可以从 /health 的 screen_w / screen_h 拿到， 自己换算像素框。

?cursor= 默认不画。1 是半透明白箭头，2 把箭头下的像素反色， 3 和 4 换成带尾巴的旧形状。箭头位置来自托盘里那个开关，不勾就只返回普通截图。

接到 MCP 客户端

服务自带一个 MCP 端点，客户端里填一个地址就能用两个工具： snapshot 返回一张当前屏幕的 JPEG，health 返回采集状态。

{
  "mcpServers": {
    "screen-kacha": {
      "type": "http",
      "url": "http://127.0.0.1:{{PORT}}/mcp"
    }
  }
}

VS Code 的 .vscode/mcp.json 用 servers 而不是 mcpServers，键名按你手上客户端的规矩来，url 这一行不用改。

协议是 2026-07-28 的无状态世代：没有 initialize 握手， 每个请求自己在 params._meta 里带 protocolVersion。 不支持这个世代的客户端会被 -32602 拒掉，这是客户端版本的问题，不是配置写错了。

宽度也可以写进文件名，160 到 3840，超出会被夹到边界： /snapshot-640.jpg 等价于 /snapshot.jpg?w=640。

给 agent

程序访问 / 时（请求头里没有 text/html）会直接拿到 llms.txt 的纯文本，不带 HTML 噪音。 浏览器访问才看到这个页面。

这个服务只抓主屏，只读。访问控制默认放行局域网、拒绝公网， 见 /error.md。
